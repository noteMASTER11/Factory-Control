# Циклические фризы телеметрии

Проверка на текущей игровой карте Factorio 2.0.77, коллектор 0.2.0, процесс 25480.

## Причина

Мод каждые 300 игровых тиков включал полный массив из примерно 18 тысяч requester-записей в `logistics.json`. Размер файла достигал 9.54 МБ. `helpers.table_to_json` и `helpers.write_file` выполняются в игровом потоке; разнесение обхода сущностей по тикам не ограничивало стоимость окончательной сериализации.

В 22-секундной записи PresentMon зафиксированы восемь стопов на 647–690 мс. Все восемь совпали с экспортом logistics.json. Без bridge/gateway за 15 секунд остались шесть стопов на 644–703 мс. Следовательно, остановка внешних чтений не устраняет причину. Сырые записи находятся в `Data/Diagnostics/stutter`, сводка сравнения — `evidence/stutter-before.json`.

Ранее проверенное среднее время коллектора скрывало такие редкие длинные операции. Benchmark с коротким начальным обходом не заменяет проверку максимальных задержек после заполнения кеша большой базы.

## Изменение 0.3.0

- Быстрый логистический снимок содержит сети, поезда, число запросчиков и ссылку на завершённый набор страниц.
- Не более 16 requester-записей сериализуется за тик. Это ограничение по записям, не гарантия фиксированного времени для произвольно большого содержимого одного сундука.
- Страницы записываются в два чередующихся каталога. Ссылка публикуется после завершения записи, до повторного использования прежнего каталога.
- Внешний bridge проверяет сессию, ревизию, номера страниц и итоговое число строк, затем восстанавливает массив для полного API. Незавершённые или перезаписанные страницы не смешиваются.
- Охват и тики измерения requester-данных сохраняются в `requesters_ref`. Содержимое полного API остаётся доступным вне игрового потока.
- Сервисы при перезапуске ожидают фактического завершения старого процесса перед запуском нового.

Проверки: Lua на 2000 запросчиках, отсутствие монолитной сериализации и повторных строк, сохранение фильтров; .NET на восстановлении страниц и отказе от несовпадающих ревизий/индексов/схем.

Для применения нужен повторный вход в карту, поскольку загруженный Lua-код не заменяется редактированием файла. Устранение фризов считается подтверждённым только после замера на 0.3.0 с заполненным набором requester-страниц.

## Проверка после обновления

В текущем процессе 10204 загружена версия 0.3.0. После начальной индексации восстановлены все 18 212 requester-записей из 1139 страниц; число строк полного HTTP API совпадает с опубликованной ссылкой, `requesters_available=true`. Быстрый `logistics.json` занимает 6770 байт вместо примерно 9.54 МБ. Ошибок Lua нет; все семь API smoke-проверок прошли. Тесты всего решения: 29 Core и 1 Desktop, Lua: 4 случая.

Повторная запись PresentMon при работающих bridge, gateway и панели: 40 секунд, 6193 кадра. Задержек более 100 мс нет, максимум 95.13 мс, p99 15.50 мс. Прежние циклические задержки 647–703 мс в этом замере не повторились. Пользователь также подтвердил исчезновение лагов. Это проверка указанного интервала и нагрузки, а не гарантия отсутствия задержек при любом дальнейшем состоянии карты.

Сводка: `evidence/stutter-after.json`; исходные кадры и события экспорта: `Data/Diagnostics/stutter/v03-*`.
