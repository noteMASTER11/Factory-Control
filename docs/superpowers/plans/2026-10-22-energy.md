# Energy Screen Implementation Plan

> **For agentic workers:** Execute directly using superpowers:executing-plans, task by task. No delegation is needed.

**Goal:** Energy screen with background models and only one rendering view.
**Architecture:** Cached delta feed → native fixed proxy → shared Web Worker → active renderer under FrameClock.
**Tech Stack:** Existing .NET/WPF/WebView2, ES modules, CSS and SVG, no new dependencies.
**Spec:** docs/energy-design.md

## Constraints and review focus

- Game collector and polling schedule remain unchanged; HTTP never scans the game.
- All UI strings live in JSON; all files/cache/temp stay on D:.
- No fabricated reserve, per-network battery charge or fuel measurements.
- Cover session reset, duplicate samples, stale data, counter restart and hidden DOM mutations.
- Keep history bounded and suppress inactive view payloads.

## Tasks

- [x] Delta feed: test SnapshotCache cursor/reset semantics, then implement client updates and one-time native power history bootstrap. Verify .NET suite.
- [x] Worker: test bounded/deduplicated history, inactive models and session reset; implement telemetry-engine/worker and energy model.
- [x] UI: implement Energy from the existing concept, make Overview render prepared models, render connection only when active, add navigation and localized strings.
- [x] Visuals and verification: global palette and CRT smoothing/RGB edges; real WebView2 at both resolutions; assert hidden panes have zero DOM mutations while worker history grows, verify 30 FPS, publish and open the normal app on the second monitor.
