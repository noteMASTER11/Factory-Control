# Factorio Monitor — архитектурное предложение

Статус: первоначальная концепция. Этап 1 реализован; текущий контракт и измеренное покрытие описаны в ../README.md и ../docs/telemetry-coverage.md. Макеты содержат демонстрационные цифры и связи. Уточнение пользователя: обычная HTML/CSS-вёрстка с hover/focus, отдельная библиотека CRT/VFX-оверлея.

## Состав
- FactoryGateway.exe: C#, ASP.NET Core, официальный MCP C# SDK, SQLite.
- FactoryMonitor.exe: WPF и WebView2; оконный/полноэкранный режим, выбор сессии.
- Интерфейс: TypeScript/React, локальные ресурсы и шрифты.
- Gateway работает без ИИ и независимо от окна. Сам выполняет фиксированные вызовы MCP, хранит снимки и историю, рассчитывает прогнозы.
- API — локальный HTTP; готовые обновления доставляются в UI через SSE.
- База вёрстки 1152×864, адаптация к 1024×768 и другим размерам, отдельный масштаб текста и плотность.
- VFX регулируются независимо: кривизна, аберрация, развёртка, послесвечение, шум и редкие глитчи.
- HTML/CSS для таблиц и форм. Реализацию общей кривизны проверить прототипом: CSS/SVG-фильтры или Canvas/WebGL-композиция. WebGL не получает DOM как готовую текстуру; постоянный захват DOM не считать готовым решением.

## Обнаружение сессий
Перечислить процессы factorio.exe: PID, доступный полный путь EXE, заголовок окна, параметры запуска. Затем отдельно проверить настроенные endpoint мостов MCP и доступность инструментов. Процесс найден / мост доступен / данные поступают — разные состояния. Путь EXE сам не определяет endpoint, название сохранения или доступ к статистике. Не извлекать данные из памяти процесса в базовом варианте. При неоднозначности предложить ручное сопоставление. Разделять историю при смене игрового источника.

## Сбор
Factorio + мод -> MCP-мост -> очередь Gateway -> кеш и SQLite -> анализатор -> API -> WebView2.

UI читает кеш; смена вкладки и число API-клиентов не порождают игровые обходы. Один ограниченный канал запросов на источник, объединение одинаковых запросов, таймауты, отмена, backoff. Интервалы из макета (энергия1с, производство2с, логистика5с, месторождения60с) предварительные, требуют измерений. Асинхронность gateway не делает вычисления внутри игры асинхронными. Дорогую работу в моде распределять по тикам и отдавать подготовленные снимки, поддерживать индексы по событиям. Показывать возраст данных, источник, игровое время и доступное покрытие. При потере связи отмечать устаревание.

## Анализатор
История за 1/5/15 игровых минут, устойчивый дефицит отдельно от кратких всплесков. При C>P время до нуля S/(C-P), до резерва B: max(0,S-B)/(C-P). Пример: P1800/мин, C1920/мин, запас2400, резерв960 -> 12мин до резерва, 20мин до нуля при неизменных потоках. Для переменных потоков — диапазон и уверенность. Учитывать доступность запасов и задержки доставки; запас логистики не равен всем предметам фабрики. Не смешивать фактическую выработку и установленную мощность. Учитывать остановки игры и смену режима спроса. Показать причины, цепочку последствий, расчёт необходимой мощности и следующий предел. Оценивать машины по действующим рецептам и производительности, когда данные доступны. При нехватке истории явно писать «Недостаточно данных». Рекомендации не меняют фабрику автоматически.

## Дополнения к прогнозу
- Приоритет может учитывать время подготовки исправления, если пользователь задал его оценку; не придумывать срок строительства.
- Фактическое потребление и потенциальный спрос различать: остановка машин из-за отсутствия сырья снижает зарегистрированный расход и может скрыть узкое место. При наличии данных оценивать спрос по активным рецептам, мощности машин и заданному целевому выпуску.
- Цель производства задаётся пользователем либо явно помечается как оценка; намеренно отключённые линии не считать обязательным спросом.
